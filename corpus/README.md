# 孙承泽专属语料库 · 使用与更新协议

> 本目录让 `scz_MBTI_explorer` 从「通用 MBTI 方法框架」变成「**专属于孙承泽的 MBTI 探索者**」。
> 建立：2026-09-03 · 种子来源：`sunccchengze/sunchengze-distilled`（本人授权的活的主本）

## 为什么需要它

仓库原有的 MBTI 能力（证据账本 / 候选集 / 相邻类型对决）是一套**方法**，但它没有主语——
SKILL.md 里的 MBTI 只是「用户临时填写的一栏」。没有语料，探索者只能反复发问卷；
有了语料，它才能做到：**先调用已知证据，只追问真正会改变结论的问题。**

## 更新协议（每次对话必读）

1. **只追加，不删改。** `memory/MEMORY.md` 按日期追加；`profile/` 里的旧证据可以**降权**但不删除——降权要写明原因与日期。
2. **分层标注，不许混。** 每条目必须属于下列之一：
   - `【一手】` — 孙承泽本人原话或本人材料原文；
   - `【档案】` — 来自既有档案（人格判定书、HANDOFF、各仓库）的转述；
   - `〔推断〕` — 由证据推导，可被推翻；
   - `【待确认】` — 未经本人确认，不得当事实使用。
3. **推断必须给推翻条件。** 任何 `〔推断〕` 都要能回答「什么现象出现时这条不成立」。
4. **对话结束前追加。** 本轮学到的新偏好、新进展、新口头禅、新的自我修正，一律写入 `memory/MEMORY.md`，带日期。
5. **MBTI 结论永远保留候选。** 不停留在「你就是 XXXX」；证据账本要同时维护领先类型、备选、反证和推翻条件。
6. **隐私红线。** 恋爱等敏感经历只作为**决策模式证据**入库，不用于对外内容；不冒充本人对外发言；家庭信息可入库但不得扩散。
7. **不造数据。** 没说过 = `【待确认】`；宁可空着，不许补全。

## 怎么用（给 Skill 的调用顺序）

```
用户提出 MBTI / 自我认知 / 决策问题
  → 读 corpus/memory/MEMORY.md（最新状态，短）
  → 读 corpus/profile/01-MBTI证据账本.md（已有候选与证据）
  → 只在结论会被改变时，读 00 / 02 / 03
  → 回答时：先给结论，再给证据 ID，最后给「什么会推翻它」
  → 对话末尾：把新证据追加进账本与活记忆
```
