# MBTI 探索者 · scz-mbti-explorer

**简体中文** | [English](README_EN.md)

> 以**孙承泽本人语料库**为主语的 MBTI 探索者：用可反证的证据账本回答「我是什么样的人、为什么会这样、怎么变强」。
> 恋爱与关系咨询是它的应用场景之一。

[![GitHub Stars](https://img.shields.io/github/stars/sunccchengze/scz_MBTI_explorer?style=social)](https://github.com/sunccchengze/scz_MBTI_explorer/stargazers)

如果它让你少一次内耗、多一次清醒，欢迎点亮一个🌟 **Star**。

大多数 MBTI 工具只有两个结果：「你是 INTJ」或「再测一次」。MBTI 探索者试图做得更认真一点：
**先调用你的已有语料，再只追问会改变结论的问题**；把候选、证据、反证和推翻条件一起交给你；
不把类型说成命运，也不把几句话包装成假精确的百分比。

它不是一个问卷生成器。它维护一份**可持续生长的本人语料库**（`corpus/`）：人物档案、26 条证据的 MBTI 账本、
表达 DNA、待补充问题队列和活记忆。它也继承了完整的恋爱军师能力——情绪支持、聊天记录分析、
关系判断与可发送话术——但现在这些是**人格探索的应用场景**，而不是全部。

## 人格探索：它能帮你解决什么

| 你遇到的问题 | 探索者会怎么帮 |
| --- | --- |
| 不知道自己到底是什么类型 | 先读已有语料，只追问会改变结论的问题；不重复发同一份问卷 |
| 纠结两个相邻类型（ENTJ 还是 INTJ） | 用高区分场景题对决，给出胜负条件，而不是让你再测一次 |
| 拿到了一个类型结论，想知道可不可信 | 审查报告是否缺候选、缺反证、缺非类型解释、缺推翻条件 |
| 想按人格差异改善沟通或成长 | 把四维和八功能翻译成可测试的沟通表达、协商方法与日常能力练习 |
| 想理解自己为什么总在同一个地方翻车 | 用决策启发式 + 已知弱点 + Big Five 竞争解释拆开"类型"与"阶段/环境" |
| **希望以后不用重复交代背景** | **语料库**：每次对话追加新证据，只追加不改旧记录，随时可查可推翻 |

工作示例（本仓语料库当前的真实结论）：

```text
领先类型：INTJ（置信度：高）
备选：ENTJ（低，阶段性排除）> INFJ ≈ ISTJ（低）；INTP 已排除
推翻条件：进组/带团队后若发现调度多人反而是能量来源 → 回摆 ENTJ
```

## 关系与沟通：作为应用场景

同一套分析内核也用于恋爱与关系问题——情绪支持、聊天记录或截图分析、关系判断、可发送话术。

| 你遇到的问题 | 它会怎么帮 |
| --- | --- |
| 不知道这句话怎么回 | 先给一条能直接发送的话，再补时机和后续分支 |
| 想追求、复联、邀约或推进关系 | 给具体行动方案，按照对方反馈继续调整 |
| 看不懂对方，或在多人之间犹豫 | 结合行为、MBTI、主观评分和现实条件给明确判断 |
| 聊天太长、截图太多 | 锁定双方说话人，区分事实、推测和未知；也可分析ChatLab已有数据 |
| 遇到冷淡、冲突、投入失衡、分手或婚姻选择 | 接住情绪，分析利弊，给下一步、观察窗口和停止条件 |
| 希望以后不用重复交代背景 | 长期记忆：首次明确同意后，跨任务记住双方档案和关键进展；可查看、暂停、撤销或清空 |

## 不预设你应该爱谁

探索者支持异性恋、男同性恋、女同性恋、双性恋、泛性恋、无性恋等不同性取向，也尊重跨性别、非二元性别及其他性别身份。它同样可以讨论单身约会、长期伴侣、婚姻、异地、再婚、跨文化关系，以及建立在知情同意基础上的非单偶关系。

系统不假设固定的性别角色：男女和多元性别用户都可以主动，任何人也都可以选择高主动模式。对于中国常见的男女性约会语境，系统可能在没有明确拒绝或不适时建议男性把主动度提高一级，但这只是可被个人偏好和现实反馈覆盖的文化校准，不是"男性必须追、女性只能等"的定律。判断依据始终是具体的人、具体行为、双方意愿和现实条件。

## 安装

将仓库克隆到 Codex 的 Skills 目录：

```bash
git clone https://github.com/sunccchengze/scz_MBTI_explorer.git ~/.codex/skills/scz-mbti-explorer
```

### 进行严肃MBTI分析

```text
使用 $scz-mbti-explorer 帮我判断更接近ENTJ还是INTJ。不要速测；请保留候选、证据、反证和能推翻结论的条件。
```

它会按轮提出低负担场景题，维护证据账本，专门比较最相邻的候选，并把 Big Five、角色、文化和压力作为竞争解释。需要审计长案例时，可用 `python3 scripts/mbti_case.py init --help` 创建本地结构；脚本只校验调查结构，**不替用户自动打出一个类型**。

涉及孙承泽本人时，它会先读 `corpus/`，先调用已有证据，只追问会改变结论的问题。

### 分析关系问题或已导出的聊天文件

```text
使用 $scz-mbti-explorer 帮我梳理情绪、分析当前关系，并给出下一步建议。
```

首次做关系咨询时，它会询问：

```text
你：MBTI / 综合评分0–100 / 主要优势和短板
对象A：代号 / MBTI / 综合评分0–100 / 当前关系
对象B（如有）：同上
经过：认识方式、发展时间、关键事件、联系和投入情况
目标：推进、确认、修复、比较选择，还是退出
情绪：目前最难受的点、强度0–10，以及是否有必须马上回复的消息
```

不知道的项目可以留空，也可以直接讲故事。Skill会从叙述中整理档案，并只追问真正会改变建议的信息。需要跨任务复用时，Skill会单独询问一次是否允许在本机保存精简档案；拒绝不影响正常使用。

ChatLab是可选依赖。安装并准备好用户自己取得的聊天导出文件后，可以直接说：

```text
使用 $scz-mbti-explorer 通过 ChatLab 分析我和对象A最近三个月的聊天。
```

它会先预览导入计划，再限定会话、对象和时间范围查询。它不会直接读取、解密或导出聊天软件数据库；没有ChatLab时仍可粘贴文字或上传截图分析。

## 一个典型回答如何产生

```text
用户叙述
  → 读取本人语料（corpus/）或建立档案
  → 情绪落地
  → 分离事实／推测／未知
  → 检索当前情境所需知识
  → 比较互惠、现实、风险与机会成本
  → 给出明确首选建议和理由
  → 生成行动、话术、观察窗口与停止条件
  → 把新证据追加回语料库
```

长期记忆和ChatLab只在用户同意或提供相应资料时按需使用，不改变这条核心分析流程。

## 孙承泽专属语料库（`corpus/`）

MBTI 分析需要三样东西：**方法论**（怎么问、怎么记账、怎么反证）、**工具**（结构化案例与审计）、**语料**（判谁、拿什么判）。
本仓库原来只有前两样——MBTI 在 `SKILL.md` 里只是"用户临时填写的一栏"。`corpus/` 补上第三样。

| 文件 | 内容 |
| --- | --- |
| `corpus/README.md` | 更新协议：只追加不删改、〔推断〕/【待确认】分层标注、推断必须给推翻条件 |
| `corpus/profile/00-孙承泽人物档案.md` | 学业坐标、技术自述基线、心智模型 M1–M5、决策启发式 13 条、社交与亲密关系、已知弱点 |
| `corpus/profile/01-MBTI证据账本.md` | 5 个候选类型、29 条证据（每条含支持/反对/非类型解释）、4 组对决、Big Five 交叉校验、推翻条件 |
| `corpus/profile/02-表达DNA与语言样本.md` | 语言指纹、反模式清单、口语样本 |
| `corpus/profile/03-待补充问题队列.md` | 下一轮最值得问的问题（按信息量排序，含"已饱和不用再问"清单） |
| `corpus/memory/MEMORY.md` | 活记忆，每轮对话追加 |
| `corpus/sources/SOURCES.md` | 来源台账与缺口清单 |

**当前工作结论**：INTJ（高置信度），备选 ENTJ > INFJ ≈ ISTJ，INTP 已排除。
这是可推翻的工作假设，不是诊断——账本里写明了改判条件。

> 语料来自 `sunccchengze/sunchengze-distilled`（本人授权的活的主本）。
> 恋爱等敏感材料只作决策模式证据，不用于对外内容；不冒充本人对外发言。

## 设计原则

1. **先调用语料，再提问。** 有证据就不重复发问卷，只问会改变结论的问题。
2. **结论必须可推翻。** 每个类型结论都带候选、反证、竞争解释和改判条件。
3. **行为比标签可靠。** 不凭MBTI、性别或一次聊天记录替他人读心。
4. **先接住人，再解决事。** 情绪没有被看见时，最正确的建议也可能无法执行。
5. **互惠比追到更重要。** 得到某一个人不是唯一胜利；减少内耗、保留尊严与未来选择权同样是成功。
6. **策略必须说明代价。** 可以讨论撒娇、推拉、节奏和表达包装，但同时交代适用条件与长期成本。
7. **同意和退出权不可绕过。** 明确拒绝不是需要破解的障碍。
8. **危险情境先保安全。** 暴力、胁迫、跟踪、诈骗和自伤风险不能用普通恋爱话术处理。
